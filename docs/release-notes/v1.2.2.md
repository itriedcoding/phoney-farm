# Phone Farm 1.2.2

The desktop build now starts. A packaging bug is fixed, and Windows still ships as one `.exe`.

## What was broken

Compose's packaged runtime only includes the JDK modules its dependency scan finds. Phone Farm's
HTTP layer loads `java.net.http` at runtime, so the installed app died immediately with
`NoClassDefFoundError: java/net/http/HttpClient` — while `gradlew run` worked, which is why it slipped
past the build. The runtime now explicitly includes `java.net.http`, `java.naming`, `java.desktop`,
`java.management`, `jdk.unsupported`, `jdk.crypto.ec` and `jdk.charsets`.

## Also in this build

- **Software rendering by default**, so the window opens on VMs, RDP sessions and machines without a
  usable GPU. `--gpu` opts into hardware rendering.
- **No silent failure:** if the window cannot open, the agent keeps running and the reason is written
  to `%USERPROFILE%\.phonefarm\desktop.log`.
- **One download:** `PhoneFarmDesktop-1.2.2.exe` is a per-user installer with shortcuts and its own
  runtime — no zip, no separate JRE, no admin rights.
- **"Failed to launch KVM":** that message comes from Android emulators (QEMU/KVM, HAXM, WHPX).
  Phone Farm Desktop uses no virtualisation. If you see it, an emulator is being started — install the
  APK on the phone itself, or run `PhoneFarmDesktop.exe` on Windows.

## Install

`PhoneFarm-1.2.2.apk` for Android 8.0+, `PhoneFarmDesktop-1.2.2.exe` for 64-bit Windows 10/11.
